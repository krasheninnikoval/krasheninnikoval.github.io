# AGENTS.md — правила проекта portfolio

## Назначение проекта

Это русскоязычное портфолио продуктового дизайнера Любови Крашенинниковой. Сайт состоит из:

- главной страницы `/` с блоком «Обо мне», опытом, проектами и контактами;
- статически сгенерированных страниц подробного описания кейсов `/cases/[slug]/`;
- служебных страниц и файлов: 404, favicon, Open Graph image, `robots.txt` и `sitemap.xml`.

Текущая реализация, визуальный язык, типографика, сетка, интервалы, цвета, радиусы и поведение интерфейса считаются эталоном. Не менять их и не «улучшать» по собственной инициативе. Любые изменения дизайн-системы допустимы только по прямой просьбе пользователя.

## Обязательный порядок работы

1. Перед началом любой задачи сначала кратко предложить план реализации.
2. Если пользователь просит варианты, сначала дать несколько вариантов с последствиями и компромиссами каждого; не выбирать за пользователя решение, которое существенно меняет результат.
3. До правок изучить относящиеся к задаче файлы и проверить существующие паттерны проекта.
4. Перед любыми изменениями Next.js прочитать релевантное руководство именно установленной версии в `node_modules/next/dist/docs/`. Не полагаться на знания о предыдущих версиях Next.js.
5. Делать минимальные, локальные изменения и переиспользовать существующие компоненты, типы, токены и контентную модель.
6. После правок выполнить как минимум `npm run lint`; для изменений маршрутов, контента, конфигурации, метаданных или сборки также выполнить `npm run build`.
7. Для визуальных изменений проверить адаптивность как минимум на ширине 360 px и на desktop, а также состояния hover, focus и reduced motion.

Если задача понятна и безопасна, после публикации плана можно приступать к ней без дополнительного подтверждения. Для необратимых действий или решений, существенно меняющих результат, сначала получить подтверждение.

## Рендеринг и публикация

- Проект собирается как полностью статический сайт: `output: "export"` в `next.config.ts`.
- Публикация выполняется в GitHub Pages из каталога `out` workflow-файлом `.github/workflows/deploy.yml` при push в `main` или ручном запуске.
- Production URL передаётся сборке через `NEXT_PUBLIC_SITE_URL`; fallback-логика находится в `src/content/site.ts`.
- Включён `trailingSlash: true`: внутренние страницы публикуются в формате `/cases/<slug>/`.
- `next/image` используется с `images.unoptimized: true`, потому что на статическом хостинге нет runtime image optimizer. Размеры исходных изображений всё равно обязательны для предотвращения layout shift.
- Динамический маршрут кейса обязан оставаться совместимым со статическим экспортом: список страниц формируется через `generateStaticParams()`.
- В Next.js 16 `params` в page/metadata асинхронный; сохранять текущий паттерн `const { slug } = await params` и типы `PageProps<"/cases/[slug]">`.
- Компоненты серверные по умолчанию. Добавлять `"use client"` только когда нужны browser API, state, effect или обработчики событий.

## Архитектура и источники данных

- `src/app/layout.tsx` — корневой layout, глобальные metadata, шрифт, consent banner и подключение Метрики.
- `src/app/page.tsx` — композиция главной страницы.
- `src/app/cases/[slug]/page.tsx` — единый шаблон страницы кейса, static params и metadata.
- `src/app/globals.css` — единственный источник глобальных дизайн-токенов, базовых стилей, focus и reveal animation.
- `src/components/` — переиспользуемые UI-компоненты. Не дублировать уже существующие `Container`, `TagList`, `MetricRow`, `MetaLine`, `CaseCard`, `CaseBlocks`, `ZoomableImage`, `CoverComposition`, `Reveal` и контактные элементы.
- `src/content/profile.ts` — профиль, hero, факты, контакты, фото и резюме.
- `src/content/projects.ts` — порядок и данные проектов на главной. Порядок объектов равен порядку отображения.
- `src/content/cases/*.ts` — данные отдельных кейсов.
- `src/content/types.ts` — контракт контента (`Project`, `CaseStudy`, `CaseBlock`, `ImageRef` и другие типы).
- `src/content/index.ts` — публичные селекторы контента, поиск кейсов и применение микротипографики.
- `src/lib/typography.ts` — автоматическая микротипографика всего пользовательского контента.
- `public/images/` — изображения; `public/Krasheninnikova-Lyubov-resume.pdf` — актуальное резюме.

Новый кейс добавлять типизированным объектом в `src/content/cases/`, подключать к соответствующему проекту в `src/content/projects.ts` и снабжать изображениями с корректными `src`, `alt`, `width`, `height`. Не верстать отдельную уникальную страницу, если задача укладывается в существующие `CaseBlock`.

## Эталонная дизайн-система

### Шрифт

- Единственный шрифт всего сайта — **Golos Text** из `next/font/google`.
- Подключение находится в `src/app/layout.tsx`: subsets `latin` и `cyrillic`, `display: "swap"`, CSS variable `--font-app-sans`.
- Глобальный стек: `var(--font-app-sans), ui-sans-serif, system-ui, sans-serif`.
- Основные начертания: regular `400` и medium `500` (`font-medium`). Не добавлять другие семейства и начертания без прямой просьбы.

### Микротипографика и редакционные правила

Весь контент из `src/content` проходит через `deepTypo()` в `src/content/index.ts`. Не расставлять вручную неразрывные пробелы и неразрывные дефисы в контентных файлах.

Текущие обязательные правила:

- короткие предлоги, союзы и частицы не остаются в конце строки;
- число не отрывается от следующего слова;
- тире не начинает новую строку;
- слова через дефис не разрываются переносом;
- финальная точка в отдельном абзаце, пункте списка, подписи или заголовке удаляется автоматически; вопросительный и восклицательный знаки сохраняются;
- технические поля `arrowPath`, `src`, `slug`, `url`, `resumeUrl`, `email`, `handle` исключены из преобразований.

### Сетка, ширины и боковые отступы

`src/components/Container.tsx` задаёт общую горизонтальную сетку:

- максимальная ширина страницы: `1600px`;
- боковые отступы: `20px` по умолчанию, `32px` от `sm` (`640px`), `40px` от `lg` (`1024px`);
- desktop-сетка основных секций: 12 колонок с gutter `32px` (`gap-x-8`);
- hero: фото занимает 3 колонки, текст 9;
- строка проекта: описание занимает 5 колонок, медиа/кейс 7;
- широкая колонка кейса и его шапка: максимум `1040px`;
- колонка для чтения: `45rem` / `720px` (`--container-reading`, класс `max-w-reading`);
- текстовые строки описаний дополнительно ограничиваются примерно `44–62ch`, где это уже задано.

Не создавать новые случайные контейнеры и боковые padding. Сначала использовать `Container`, `max-w-reading` или существующую широкую колонку `max-w-[1040px]`.

### Вертикальные интервалы

Базовая шкала — стандартные шаги Tailwind 4 px; текущие крупные интервалы являются частью композиции:

- блоки тела кейса: `56px` между блоками, `80px` от `sm` (`space-y-14 sm:space-y-20`);
- подчинённый блок кейса приближается к родителю на `32px` / `48px`;
- основные проекты: `96px` / `112px` (`space-y-24 sm:space-y-28`);
- секция «Другие проекты» отделена сверху на `144px` / `192px`;
- внутренние локальные интервалы обычно `12`, `16`, `20`, `24`, `32`, `40`, `48`, `56` и `64px`; переиспользовать существующий ритм ближайшего компонента;
- footer: вертикальный padding `64px` / `80px`;
- страницы кейсов: верхний padding `96px` / `112px`, нижний `96px`.

Не уплотнять и не растягивать эти интервалы без прямого запроса. При новом блоке ориентироваться на соседний существующий паттерн, а не вводить новое значение.

### Скругления, рамки и тени

- `--radius-card: 1rem` / `16px` — карточки, большие изображения, подложки и fact cards.
- `--radius-media: 0.75rem` / `12px` — вложенные изображения и медиа.
- Интерактивные chips, теги, CTA, header и кнопки cookie banner — `rounded-full`.
- Клавиатурный focus: `2px solid ink`, offset `3px`, radius `4px`.
- Рамки — преимущественно `1px` цветов `line` или `edge`.
- Тени используются деликатно и уже настроены в `Header`, `CaseCard`, `CoverComposition` и `ZoomableImage`. Не добавлять новые тяжёлые тени без запроса.

### Адаптивность, изображения и анимация

- Минимальная целевая ширина — `360px`.
- Основные breakpoints текущей вёрстки: `sm = 640px`, `lg = 1024px`, местами `2xl = 1536px`.
- Изображения выводить через `next/image`, всегда задавать корректные intrinsic `width`/`height`, осмысленный `alt` и подходящий `sizes`.
- Скриншоты интерфейсов в кейсах должны сохранять возможность увеличения через `ZoomableImage`.
- Reveal animation: `0.6s`, смещение снизу `12px`, easing `cubic-bezier(0.16, 1, 0.3, 1)`.
- Обязательно сохранять поддержку `prefers-reduced-motion`: контент видим без анимации, transitions/animations практически отключаются.
- Без JavaScript контент с `.reveal` должен оставаться доступным благодаря fallback в root layout.

## Яндекс Метрика — не ломать

На сайте работает Яндекс Метрика, счётчик **`112490864`**. Текущая интеграция — часть production-контракта и должна сохраняться при любых изменениях.

- Конфигурация и consent storage: `src/lib/metrika.ts`.
- Подключение tracker: `src/app/layout.tsx` и `src/components/Metrika.tsx`.
- Consent UI: `src/components/CookieNotice.tsx`.
- Счётчик загружается только в production и только после согласия пользователя (`metrika-consent = accepted`).
- Включены `webvisor`, `clickmap`, `trackLinks`, `accurateTrackBounce`.
- Клиентские переходы отправляют `hit` при изменении pathname.
- Делегированный обработчик кликов отправляет цели:
  - `email` для ссылок `mailto:`;
  - `telegram` для ссылок, содержащих `t.me/`;
  - `resume` для ссылок на `.pdf`.

Запрещено без отдельной задачи:

- менять ID счётчика, имена целей, consent key или момент загрузки скрипта;
- удалять `MetrikaTracker`, `CookieNotice`, event delegation или SPA pageview tracking;
- менять целевые `href` так, чтобы они перестали распознаваться (`mailto:`, `t.me/`, `.pdf`);
- отправлять аналитику до согласия или включать Метрику в development;
- заменять обычные ссылки целевых действий на элементы без корректного `href`.

При изменении навигации, контактных кнопок, резюме, layout или клиентского роутинга отдельно проверить, что цели и pageviews продолжают отправляться после согласия.

## SEO и доступность

- Сохранять metadata из `src/app/layout.tsx` и per-case metadata из страницы кейса.
- Сохранять JSON-LD `Person` на главной, Open Graph image, favicon, `robots.ts` и `sitemap.ts`.
- Скрытые/черновые кейсы не должны индексироваться или случайно попадать в публичные списки.
- Использовать семантические элементы, корректную иерархию заголовков, доступные имена кнопок и диалогов.
- Все интерактивные элементы должны работать с клавиатуры; текущий `focus-visible` не удалять.
- Внешние ссылки, открываемые в новой вкладке, сохраняют `rel="noreferrer noopener"`.
